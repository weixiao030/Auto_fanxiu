# 多人秘境托管（0.48）

适配凡修0.2.116。根据本机已有恢复脚本核对原生状态机；本轮 IDA 服务可连接但没有打开的数据库，没有新增引擎反编译结果。

- 托管开关管理已有场次；自动空载入场为独立选项，默认关闭。免费次数优先，钥匙在计划和执行前分别遵守当前物品保护、绑定预算与固定锁。
- 入场前检查原生角色资格、开放状态与库存；准备接口返回已有场次时交给原生恢复。预留、网络结果不明及结算阶段沿用原生确认，不重复入场，也不取消排队。
- 修正字典合并未覆盖 `active=false` 导致场次误判的问题。计划器和桥接均阻止其他玩法旧计划打断已有场次。
- 场内新鲜状态与原生保持35秒一致。原生标记过期、操作待确认、事件过期或禁用时不派发动作。已有场次隐藏时恢复原生视图后再托管。
- 战斗生命未同步不当作零血。达到生命或时长阈值且原生允许时撤离；当前客户端没有战斗逃脱方法，界面隐藏对应设置。战斗、探索推进、采集和结算由原生执行。
- 优先使用服务器 `entered_at`；缺字段时用当前桥接第一次观察该场次起的单调时长。后者是保守下界，助手重载会重新观察，不冒充真实入场时间。
- 事件选项留空沿用原生策略；指定编号仅匹配当前事件的未禁用、未过期选项。服务器票据和同请求回执负责确认。

卡片状态按当前快照重新计算，分别显示未开放、自动入场关闭、检查中、资格不足、入场确认、探索、事件、战斗、撤离与结算；旧提示不会因开放状态恢复而残留。`mp_interval` 是入场条件检查间隔，不是场内轮询间隔。时长和生命阈值是撤离触发条件，不保证立即脱离战斗或秒级退出。

验证覆盖隔离计划器、桥接生命周期、35秒边界、未知生命、计时、入场恢复和浏览器状态切换。按用户要求不新增多人秘境完整实机场次或30分钟等待；未将隔离结果描述为实机全流程完成。
